## 内存模型

至少分开记录三类资源：

1. JS heap：对象、数组、字符串、函数、闭包、页面数据、解析结果和模块状态。
2. 图片池：解码后的位图、动画帧和渲染侧缓存。
3. 存储/包体：资源文件、内部文件和 HAP 大小，不等于运行时内存。

“文件只有 20 KB”不能证明加载后只占 20 KB。“图片池独立”也不能证明图片切换不影响 JS heap 或页面生命周期。

## JS heap 规则

- 64 KB 档：只保留当前页面和当前操作所需状态。数据表拆成小文件，按索引读取；禁止大字典和完整历史常驻。
- 256 KB 档：允许小型有限缓存，但必须有明确上限和淘汰点。
- 512 KB 档：仍使用分片和懒加载；额外空间用于功能与峰值余量，不用于引入通用框架。
- 未知档：按 64 KB 实现并标记待真机确认。

把内存评估写成“常驻 + 操作峰值 + 框架/未知余量”，不要只统计源码文件大小。持久状态尽量保持在目标 heap 的较小部分；具体安全比例必须由目标真机压力测试决定。

采用以下实现方式：

- 以标量和短字符串表达页面状态。
- 将长文本、关卡、棋谱、词典和媒体列表拆分为独立文件；索引只保存偏移、ID 或文件名。
- 顺序异步读取，处理完就解除引用；避免同时发起大量读取回调。
- 限制历史、存档、日志、缓存、动画帧数组和待处理任务。
- 复用工作数组/对象；循环中避免创建闭包、正则、临时对象和级联字符串。
- 对高频传感器回调节流，仅更新 UI 所需的最新值。
- 使用 `var`、普通函数表达式和传统循环作为新增表端代码的强制风格；完整规则见 `jerryscript-syntax.md`。

## 峰值风险

重点审查以下瞬时叠加：

- `file.readText` 返回完整字符串后再 `JSON.parse`，同时存在原字符串、对象树和业务副本。
- 字符串反复 `+=`，产生多个中间字符串。
- `JSON.stringify` 同时保留原对象与完整序列化字符串。
- `map/filter/reduce/slice/concat/spread` 产生新数组。
- 页面跳转时旧页面、路由参数和新页面状态同时存活。
- 多个异步请求的回调闭包捕获页面或大型数据。
- 异常路径没有释放计时器、媒体对象、订阅或图片引用。

对这些路径按最大输入做压力测试，而不是只测空数据。

## 图片池规则

用 `宽 * 高 * 4` 估算单张 RGBA 解码占用：

| 尺寸 | 近似解码占用 |
|---:|---:|
| 466x466 | 0.83 MiB |
| 454x454 | 0.79 MiB |
| 408x480 | 0.75 MiB |
| 390x390 | 0.58 MiB |
| 336x396 | 0.51 MiB |
| 336x306 | 0.39 MiB |

真实值会受像素格式、对齐、缩放副本和引擎缓存影响。动画帧、遮罩、背景、CG、角色立绘和离屏图片要合并计算最大并发数。

优先：预缩放素材、减少透明全屏层、复用同一路径、分段动画、离场后清空绑定。若连续换图导致真机图片池不回落，可保存当前最小状态后用 `router.replaceUrl` 重建页面；此方案必须验证不会造成路由循环、存档损坏或交互丢失。

## 生命周期

在页面中集中维护资源句柄：

```javascript
onDestroy: function() {
  if (this.timer) {
    clearInterval(this.timer);
    this.timer = null;
  }
  sensor.unsubscribeAccelerometer();
  this.largeData = null;
  this.imageList = [];
}
```

根据实际接口只取消已经成功订阅的能力，并处理重复进入页面。所有 `setInterval`、递归 `setTimeout`、动画、媒体播放和订阅都必须能停止。

## 禁止模式

- 在表端加载 QuickJS、Babel、webpack、解释器或大型 polyfill。
- 在新增表端代码中使用 `let/const`、箭头函数、方法简写、`class`、模板字符串、解构、扩展/剩余参数、默认参数、`for...of`、生成器、可选链、空值合并、动态导入、`async/await` 或 Promise。
- 直接把 Web、Node.js、ArkTS 或手机 Wearable 代码粘贴进 Lite 工程。
- 将巨型数组/对象字面量放在模块顶层。
- 依赖 GC 在特定时刻自动释放关键资源。
- 为换图保留多个不可见全屏图层。
- 无界缓存、无界日志、无界存档或无限递归定时器。
- 只看模拟器流畅就宣称内存安全。

## 评审清单

- 目标 heap 是否明确，未知时是否按 64 KB。
- 最大文件读取、JSON 解析和序列化峰值是否估算。
- 页面 `data`、模块顶层、闭包和缓存是否有大对象。
- 每个定时器/订阅/媒体/动画是否有停止点。
- 最大并发解码图片数是否列出。
- 图片是否按实际显示尺寸预处理。
- 反复进入/退出、连续换图、快速点击和长时间运行是否真机测试。
