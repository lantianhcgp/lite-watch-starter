# 安装/开发错误码总表（论坛整理 + 实战注解）

原文表格由用户 2026-10-03 从华为开发者论坛找到（称"可靠的报错对应表"），原文保留；
`⚠实战注解` 为本项目（elcton CI 链路）实测补充。报错优先按此表对码，再查
[build-install-error-catalog.md](build-install-error-catalog.md) 的根因细节。

## 安装可能遇到的错误码

| 码 | 现象 | 表格解法 |
|---|---|---|
| 23 | 更新失败，安装的应用版本过低 | 卸载旧的再安装；或用新的包名签名应用 |
| 24 | 已安装应用数量达到上限 | 重启手表 |
| 27 | 更新失败，与旧版本签名信息不匹配 | 卸载旧的再安装；或用原先的 p7b 文件签名应用 |
| 30 | 签名验证失败 | 关闭 WLAN 再安装，不行再签一次 |
| 31 | 签名验证失败 | 签错了，重签 |
| 47 | 配置文件 app.apiVersion 字段不合法 | 手表版本太低不兼容；或改 config.json 里的 API 版本 |

## 开发者可能遇到的错误码

| 码 | 现象 | 表格解法 |
|---|---|---|
| 10 | 内部错误 | 配置/项目问题？未签名？ |
| 28 | 签名验证失败 | **签名时的包名要和 config.json 的包名一致** |
| 34 | 内部错误 | 单个 js 页面过大，超过 48KB |
| 40 | 配置文件格式错误 | compileSDK 配置问题；label $string 名字过长超 22 字符；应用图标太大 |
| 82 | 内部错误 | 手表不支持 i18n？删 i18n 和 zh-CN、en-US 目录 |

## ⚠ 实战注解（2026-10-03，GitHub Actions CI 链路）

- **40 与 28 的分工**：40=配置格式（compileSDK/label/图标三项），28=包名与签名不一致。
  先看码再猜——40 不是签名问题。
- **40 三项的落地修法**：`build-profile.json5` 补 `"compileSdkVersion": "6.1.1(24)"`（字符串格式）；
  label ≤22 字符；icon.png ≤48x48、icon_small.png ≤32x32（clan 实测 104/92 被拒）。
- **同 bundle = 更新（覆盖数据）**：包名相同的安装会被当成更新，危险。
  实测现役课程表 bundle=`<旧证书包名>`（8 月网站工具把 config 改写成证书包名所致）——
  **禁止**再用签过课程表的老证书以 FORCE 改包名方式签其他应用，否则覆盖课程表数据。
  多项目并存：各项目保留自己的 config 包名（表端是否强校验 28 待实测），或每项目单独 p7b。
- **读包内包名的方法**：signed.bin 结构 = `0xBE` + int32 长度 + bundleName，
  后续字节里可 grep `"bundleName":"..."`（config.json 内嵌）。用于装前核对身份。
- 82（i18n）：elcton/clan 均含 i18n 目录，FIT3 若报 82 按表删除。
- 34（48KB/页）：课程表数据页注意分页，别单页塞整学期 JSON。
